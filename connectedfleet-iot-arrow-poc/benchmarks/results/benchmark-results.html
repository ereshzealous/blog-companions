Four ways to load the same Kafka events into ClickHouse, compared on equal terms: the official ClickHouse sink (as first configured and tuned), a Python row worker and a Python Arrow worker. Every chart below is computed from the saved run files; every run ever made is listed at the end.

One laptop, one node of each service. These runs compare lanes on equal terms; they do not establish production capacity or high availability.

Run these experiments · commands and output files

From the POC directory, with Docker (about 12 GiB for the containers):

make up init seed
make lab-02                      # correctness first
make lab-03 PROFILE=confirm      # rebuilds the worker image; waits for a quiet host per case
make report                      # re-validate every run, regenerate aggregates
make results-html                # this page and every run's report.html

Each run writes benchmarks/results/runs/<run_id>/: run.json (every case, settings, versions, host-guard record), validation.json, metrics.csv, phase-metrics.csv, samples.jsonl and the console log.
